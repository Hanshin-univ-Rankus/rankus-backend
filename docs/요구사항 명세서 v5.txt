🔖 3.3 캘린더 기능 [대폭 개편 - 페이지 분리]

🎯 3.3.1 캘린더 시스템 개요
	•	핵심 컨셉: 일반일정과 면접일정 완전 분리
	•	페이지 구성: 별도 페이지로 완전 분리된 캘린더 시스템
	•	기술 철학: 각 캘린더의 고유 목적에 집중한 전용 인터페이스

🔧 3.3.2 일반일정 캘린더 페이지

페이지 구성:
	•	독립 페이지: /labs/{labId}/calendar/schedules
	•	페이지 제목: "일반일정 캘린더"
	•	네비게이션: 상단 탭으로 면접일정 캘린더 이동 가능

기능:
	•	일반일정 생성: 시간이 없는 종일 이벤트 생성
		- 일정 제목, 내용, 날짜, 장소 입력
		- 관련 공지사항 연결 기능 (다:다 관계)
	•	일정 수정: 생성된 일정 정보 변경
	•	일정 삭제: 불필요한 일정 제거
	•	일정 상세 보기: 개별 일정의 자세한 정보 표시

화면 구성:
	•	월별 캘린더 뷰: 한 달 전체 일정 표시
	•	색상 구분: 초록색 계열로 통일
	•	일정 표시: 각 날짜에 최대 3개 일정 표시
	•	더보기 기능: 3개 초과 시 "더보기" 버튼 표시
	•	액션 버튼: "새 일정 추가" 버튼 (권한 있는 사용자만)

일정 상세 화면:
	•	기본 정보: 제목, 내용, 날짜, 장소
	•	연결된 공지사항: 관련 공지사항 목록 표시
		- 공지사항 제목, 요약, 작성일 표시
		- 공지사항 바로가기 링크 제공
	•	편집 권한: 권한 있는 사용자만 수정/삭제 가능

🔧 3.3.3 면접일정 캘린더 페이지

페이지 구성:
	•	독립 페이지: /labs/{labId}/calendar/interviews
	•	페이지 제목: "면접일정 캘린더"
	•	네비게이션: 상단 탭으로 일반일정 캘린더 이동 가능

기능 (자동 관리):
	•	자동 생성: 면접 생성 시 캘린더에 자동 추가
		- 면접 시작일과 종료일에 각각 캘린더 이벤트 생성
		- 기본 시간: 9:00-18:00 (면접 가능 시간대)
		- 생성자: 랩장 자동 설정
	•	자동 업데이트: 지원자 신청 시 이름 자동 표시
		- 지원자 실명으로 표시 (예: "김학생, 이학생")
	•	상태 동기화: 면접 상태 변경 시 캘린더 반영
		- 면접 취소 시 캘린더에서도 취소 표시
	•	수정 제한: 자동 생성된 면접 일정은 수정 불가
	•	완료 처리: 면접 완료 후 관리자가 수동으로 완료 처리

화면 구성:
	•	월별 캘린더 뷰: 면접 일정만 표시
	•	색상 구분: 주황색 계열로 통일
	•	상태 표시: 예정/진행/완료/취소 상태별 시각적 구분
	•	필터 기능: 상태별 필터 (예정/진행/완료/취소)
	•	액션 버튼: "면접 완료 처리" 버튼 (권한 있는 사용자만)

면접 상세 화면:
	•	기본 정보: 면접 제목, 날짜, 시간 (9:00-18:00)
	•	면접 정보: 면접실, 면접 기간 (시작일~종료일)
	•	지원자 정보: 지원자 실명 목록
	•	슬롯 정보: 실제 면접 가능 시간대 목록
	•	상태 정보: 현재 면접 상태
	•	주의사항: 실제 신청은 관리자가 생성한 면접 슬롯 시간에만 가능

🔧 3.3.4 면접 시스템 연동 상세

자동 연동 기능:
	•	면접 생성 시: Interview 생성 시 캘린더 이벤트 자동 생성
		- 면접 시작일 캘린더 이벤트: "면접 시작 - {랩실명}"
		- 면접 종료일 캘린더 이벤트: "면접 종료 - {랩실명}" (시작일과 다른 경우)
	•	지원자 신청 시: LabApplication 생성 시 지원자 이름 자동 표시
		- 지원자 목록 실시간 업데이트
		- 지원자 없을 시: "지원자 모집중" 표시
	•	면접 취소 시: Interview 상태 변경 시 캘린더 자동 반영
		- 면접 상태 CLOSED → 캘린더 상태 CANCELLED

면접 캘린더 특징:
	•	시간 표시: 9:00-18:00 (면접 가능 시간대 표시)
	•	실제 운영: 관리자가 생성한 InterviewSlot 시간에만 실제 신청 가능
	•	지원자 표시: 실명으로 표시 (개인정보 보호 논의 완료)
	•	완료 처리: 면접 완료 후 관리자가 수동으로 완료 처리
	•	데이터 일관성: 면접 시스템에서만 수정 가능 (캘린더에서 수정 불가)

🔧 3.3.5 캘린더 네비게이션 및 공통 기능

페이지 간 전환:
	•	탭 방식: 페이지 상단에 "일반일정" / "면접일정" 탭 배치
	•	즉시 전환: 탭 클릭 시 해당 캘린더 페이지로 즉시 이동
	•	상태 유지: 월/년도 선택 상태는 페이지 전환 시에도 유지

공통 기능:
	•	월 이동: 이전/다음 달 이동 버튼
	•	오늘로 이동: 현재 날짜로 이동 버튼
	•	새로고침: 최신 정보 업데이트 버튼
	•	반응형 디자인: 모바일 환경에서도 최적화된 사용자 경험

🔧 3.3.6 권한 체계

권한별 기능:
	•	랩실 부원: 자신의 랩 캘린더 조회만 가능
	•	랩 매니저/랩장: 자신의 랩 캘린더 조회 및 일반일정 CRUD
	•	교수/Admin: 모든 랩 캘린더 조회 및 일반일정 CRUD
	•	면접일정: 모든 사용자 조회 가능, 편집은 시스템에서 자동 처리

🔖 3.4 투표 시스템 [신규 추가]

🎯 3.4.1 투표 시스템 개요
	•	핵심 컨셉: 랩실 내 민주적 의사결정 지원
	•	권한 체계: 역할 기반 접근 제어
	•	투표 형태: 단일 선택형 투표 (2~5개 선택지)

🔧 3.4.2 투표 권한 체계

투표 참여 권한:
	•	랩 멤버 (LAB_MEMBER): 자신의 랩 투표 조회 및 참여
	•	랩 매니저 (LAB_MANAGER): 자신의 랩 투표 조회 및 참여
	•	랩장 (LAB_LEADER): 자신의 랩 투표 조회 및 참여
	•	교수 (PROFESSOR): 모든 랩 투표 조회 및 참여
	•	관리자 (ADMIN): 모든 랩 투표 조회 및 참여

투표 생성 권한:
	•	랩 매니저 (LAB_MANAGER): 자신의 랩 투표 생성
	•	랩장 (LAB_LEADER): 자신의 랩 투표 생성
	•	교수 (PROFESSOR): 모든 랩 투표 생성
	•	관리자 (ADMIN): 모든 랩 투표 생성

투표 삭제 권한:
	•	투표 작성자: 자신이 생성한 투표 삭제
	•	해당 랩장: 자신의 랩 투표 삭제
	•	교수 (PROFESSOR): 모든 랩 투표 삭제
	•	관리자 (ADMIN): 모든 랩 투표 삭제

🔧 3.4.3 투표 생성 및 관리

투표 생성:
	•	투표 제목: 최대 100자
	•	투표 내용: 최대 500자
	•	선택지: 최소 2개, 최대 5개 (각 선택지 최대 50자)
	•	마감시간: 현재 시간 이후 설정 가능
	•	투표 상태: ACTIVE (진행중), CLOSED (마감)

투표 관리:
	•	투표 수정: 구현하지 않음 (단순화)
	•	투표 삭제: 권한자만 삭제 가능, 참여 기록도 함께 삭제
	•	수동 마감: 투표 생성자 및 권한자가 언제든 마감 가능
	•	자동 마감: 설정된 마감시간에 자동 마감

🔧 3.4.4 투표 참여 및 결과

투표 참여:
	•	단일 선택: 하나의 선택지만 선택 가능
	•	중복 방지: 한 번 투표하면 변경 불가
	•	참여 자격: 해당 랩 소속 + ENROLLED 상태 확인
	•	마감 후 참여 불가

투표 결과 조회:
	•	조회 권한: 모든 랩 멤버 (투표 참여 가능 권한과 동일)
	•	실시간 조회: 투표 진행 중에도 결과 조회 가능
	•	통계 정보: 각 선택지별 투표 수, 전체 참여율
	•	마감 후: 최종 결과 확정 표시

🔧 3.4.5 투표 목록 및 조회

투표 목록:
	•	정렬 기준: 생성일 내림차순
	•	상태 표시: 진행중/마감 상태 구분
	•	참여 상태: 본인 투표 여부 표시
	•	페이징: 대량 투표 목록 처리

투표 상세:
	•	투표 정보: 제목, 내용, 생성자, 마감시간
	•	선택지 목록: 각 선택지별 투표 수 및 비율
	•	참여 현황: 전체 참여자 수 / 전체 랩 멤버 수
	•	투표 버튼: 미참여 시 투표 버튼 표시

🔧 3.4.6 데이터 모델 설계

투표 테이블:
CREATE TABLE votes (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(100) NOT NULL,
    content VARCHAR(500),
    status ENUM('ACTIVE', 'CLOSED') NOT NULL,
    deadline DATETIME NOT NULL,
    lab_id BIGINT NOT NULL,
    created_by BIGINT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    FOREIGN KEY (lab_id) REFERENCES labs(id),
    FOREIGN KEY (created_by) REFERENCES users(id),
    INDEX idx_lab_status_created (lab_id, status, created_at)
);

선택지 테이블:
CREATE TABLE vote_choices (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    vote_id BIGINT NOT NULL,
    choice_text VARCHAR(50) NOT NULL,
    choice_order INT NOT NULL,
    vote_count INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    FOREIGN KEY (vote_id) REFERENCES votes(id) ON DELETE CASCADE,
    UNIQUE KEY uk_vote_choice_order (vote_id, choice_order)
);

투표 참여 테이블:
CREATE TABLE vote_participations (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    vote_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    choice_id BIGINT NOT NULL,
    voted_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    FOREIGN KEY (vote_id) REFERENCES votes(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (choice_id) REFERENCES vote_choices(id),
    UNIQUE KEY uk_vote_user (vote_id, user_id)
);

🔧 3.4.7 투표 시스템 개발 우선순위

Phase 1: 핵심 기능 구현 (2주)
	•	1주차: 도메인 모델 및 데이터베이스 설계
		- Vote, VoteChoice, VoteParticipation 엔티티
		- Repository 및 기본 CRUD 서비스
		- 투표 생성 및 삭제 API
	•	2주차: 투표 참여 및 결과 조회
