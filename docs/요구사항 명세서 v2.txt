📌 4. 랩실 랭킹 기능 (상세 확정)

🔖 4.1 점수 신청 시스템
	•	점수 신청 방식: 자유 신청 (언제든지 가능)
	•	신청 필수 정보: 카테고리, 성과내용, 취득일자, 증빙서류
	•	신청 선택 정보: 신청 사유, 관련 링크, 공개/비공개 설정
	•	파일 업로드 제한: PDF, 이미지 파일 (JPG, PNG, JPEG), 개당 10MB 이하
	•	파일 검증: MIME 타입 + 파일 내용 검증 (악성 파일 방지)
	•	업로드 실패 시: 신청 전체 삭제 처리
	•	보안 검증: 확장자, MIME 타입, 매직 넘버 검증 단계적 적용

🔖 4.2 점수 카테고리 및 배점 기준
	•	학업 성과
		- 전공 A+ 취득: 5점/과목
		- 학과 성적 장학금: 15점
		- 학점 4.0 이상 유지: 10점/학기
	•	대회 수상
		- 교내 대회: 대상 30점, 금상 20점, 은상 10점
		- 교외 대회: 대상 50점, 금상 30점
	•	자격증
		- 국가 기술자격증: 20점
		- 국제 인증 자격증: 25점
		- 민간 자격증: 10점
	•	교육/연수
		- 교육 프로그램 수료: 10점
		- 외부 세미나 참석: 5점
	•	연구 활동
		- 논문 게재 (SCI): 100점
		- 논문 게재 (일반): 50점
		- 특허 출원: 30점
	•	카테고리 관리: 개발자가 개발시 수정 (수정하기 쉽도록 코드 설계)
	•	점수 수정 적용: 기존 점수에 소급 적용

🔖 4.3 승인 프로세스
	•	승인 권한: 해당 랩의 랩장 + admin, 교수 (모든 랩실 기여 가능)
	•	승인 기한: 6개월 (기한 초과 시 자동 거부)
	•	자동 거부 후: 재신청 가능
	•	승인자 기록: 승인 후 승인자 정보 저장
	•	동시 승인 방지: 먼저 승인한 사람 기준으로 처리

🔖 4.4 중복 방지 시스템
	•	중복 검사 기준: 카테고리, 취득일자 조합
	•	구현 방식: 애플리케이션 로직 + 데이터베이스 유니크 제약조건 조합
	•	날짜만 중복: 노란색 경고 + 상단 배치 + 사용자 가이드 제공
	•	날짜 + 카테고리 모두 중복: 빨간색 테두리 경고 + 상단 배치 + 중복 해결 안내
	•	중복 확인: 승인 전 신청자의 모든 기록 조회 후 최종 승인
	•	동시성 제어: 데이터베이스 제약조건으로 Race Condition 방지

🔖 4.5 점수 정정 시스템
	•	정정 권한: 승인 권한이 있는 모든 사람 (랩장, admin, 교수)
	•	정정 횟수: 한번만 가능
	•	상태 변경 규칙:
		- 승인 → 거절: 언제든지 가능
		- 거절 → 승인: 정정 내역이 한번도 없을 때만 가능
	•	기록 보관: 정정 이유만 보관, 최초 승인자도 기록

🔖 4.6 랭킹 시스템
	•	랩실 점수 산정: 부원들 총합점수
	•	다중 소속 처리: 현재 미지원 (단일 랩실 소속만 지원)
	•	동점 처리: 동점자들 모두 같은 등수 (1, 2, 2, 4등)
	•	랭킹 업데이트: 실시간 처리 → 추후 배치 처리 전환 (설정 기반)
	•	성능 최적화: 캐싱 전략 적용 (랩별 점수 캐시 + 전체 랭킹 캐시)
	•	계산 투명성: 랭킹 계산 과정 공개 (카테고리별 점수 분포, 월별 추이)

🔖 4.7 랭킹 공개 범위
	•	랩실 토탈 랭킹: 전체 사용자 조회 가능
	•	개인 기여 점수: 본인 + 랩장 + admin + 교수만 조회
	•	개인 기여도 공개 설정: 기본값 전체 공개, 옵션 (전체 공개/랩원만 공개/비공개)
	•	상위 기여자: 현재 소속 인원 중 상위 5명까지 부원 모두가 조회 가능 (점수만)

🔖 4.8 랩실 이동 및 졸업 처리
	•	다중 소속: 현재 미지원 (단일 랩실 소속만 지원, 추후 확장 예정)
	•	현재 구조: 기존 users.lab_id 단일 소속 필드 활용
	•	탈퇴 시: 해당 랩에서 점수 삭제
	•	졸업 처리 권한: 소속 랩장, admin, 교수
	•	졸업 처리 방식: 처리 즉시 모든 점수 삭제, 취소 불가능
	•	졸업 처리 복구: 관리자 권한으로 복구 가능 (후순위 개발)
	•	랩실 해체 시: 관련 모든 점수 삭제
	•	확장 계획: UserLabMembership 엔티티 추가로 다중 소속 지원

🔖 4.9 시스템 운영 정책
	•	점수 변동 이력: 관리하지 않음
	•	통계 및 분석 기능: 후순위 개발
	•	자동 거부 전 알림: 후순위 개발
	•	성능 최적화: 소규모 서비스 기준으로 단계적 적용 (실시간 → 배치)
	•	감사 로그: 모든 승인/거부/정정 액션 기록 (사용자, 시간, 사유, IP)
	•	모니터링: 시스템 건강성 체크 (승인 대기 수, 만료 임박 수, 성능 지표)
	•	관리자 도구: 대시보드, 문제 신청 목록, 시스템 설정 관리

📌 7. 랭킹 시스템 기술적 고려사항

🔖 7.1 데이터베이스 설계 결정사항
	•	중복 방지: 유니크 제약조건 + 애플리케이션 로직 조합으로 Race Condition 방지
	•	인덱스 설계: 복합 인덱스 (applicant_id, achieved_at, category) 성능 최적화
	•	파티셔닝: 연도별 데이터 분할 고려 (장기 확장 시)

🔖 7.2 보안 및 권한 체계
	•	파일 업로드 보안: 확장자 + MIME 타입 + 매직 넘버 검증 단계적 적용
	•	권한 체계 단순화: 랩장, 교수, 관리자만 승인 (임원 제외)
	•	감사 로그: 모든 승인/거부/정정 액션 추적 (사용자, 시간, 사유, IP)

🔖 7.3 성능 최적화 전략
	•	실시간 → 배치 처리 전환: 설정 기반 점진적 적용
	•	캐싱 전략: 랩별 점수 캐시 + 전체 랭킹 캐시 (Redis 활용)
	•	데이터베이스 최적화: 읽기 전용 복제본 활용 고려

🔖 7.4 사용자 경험 고려사항
	•	중복 경고 UX: 실시간 검사 + 사용자 친화적 가이드 제공
	•	승인 상태 투명성: 상세한 진행 상황 + 다음 액션 안내
	•	랭킹 계산 투명성: 카테고리별 점수 분포 + 월별 추이 공개

🔖 7.5 운영 및 모니터링
	•	시스템 건강성 체크: 승인 대기 수, 만료 임박 수, 성능 지표 모니터링
	•	관리자 도구: 대시보드, 문제 신청 목록, 시스템 설정 관리
	•	비즈니스 메트릭: 신청 수, 승인 시간, 랭킹 계산 성능 추적
