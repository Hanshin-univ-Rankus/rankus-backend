🔖 3.2 QR 출석 시스템 (소규모 특화) [대폭 확장]

🎯 3.2.1 시스템 개요
	•	대상 환경: 랩당 5-20명 소규모 그룹 특화
	•	핵심 가치: 복잡한 설정 없이 원클릭으로 출석 시작 및 관리
	•	기술 철학: 기존 인프라 활용, 단순하지만 효과적인 기능

🔧 3.2.2 출석 세션 관리 (관리자 기능)

원클릭 출석 시작:
	•	자동 설정 항목:
		- 일정: 오늘 날짜 자동 설정
		- 대상: 랩 소속 전체 멤버 자동 선택
		- 유효시간: 5분 기본값 (1-10분 조절 가능)
		- 제목: "랩 출석 (날짜)" 자동 생성
	•	즉시 결과: QR 코드 생성 및 출석 화면 표시

실시간 출석 현황 모니터링:
	•	출석 현황: 이름 목록 + 출석 상태 (❌→✅→△)
	•	진행률: "5명 중 3명 출석" 간단 표시
	•	남은 시간: 카운트다운 표시
	•	자동 새로고침: 3초마다 상태 업데이트

출석 정정 (즉시 가능):
	•	원클릭 정정: 이름 클릭으로 출석/지각/결석 순환
	•	정정 이유: 간단한 메모 (선택사항)
	•	즉시 반영: 정정 내용 실시간 반영
	•	정정 이력: 정정 시간 및 담당자 기록

📱 3.2.3 QR 코드 기반 출석 (사용자 기능)

QR 코드 스캔 및 출석 처리:
	•	접근 방법: 휴대폰 카메라 또는 QR 스캐너 앱
	•	보안: JWT 기반 일회용 토큰 (세션별 고유)
	•	유효성: 세션 유효시간 내에서만 인식
	•	출석 완료: "출석 완료!" 메시지 + 진동 피드백
	•	중복 방지: 동일 세션 내 1회 출석만 허용

사용자 친화적 에러 처리:
	•	QR 스캔 실패: 친근한 에러 메시지 + 재시도 가능
	•	세션 만료: "출석 시간이 종료되었습니다" 안내
	•	중복 출석: "이미 출석하셨습니다" 안내

🗄️ 3.2.4 데이터 모델 설계

AttendanceSession (출석 세션):
CREATE TABLE attendance_sessions (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    lab_id BIGINT NOT NULL,
    title VARCHAR(200) NOT NULL,
    description TEXT,
    created_by BIGINT NOT NULL,
    started_at TIMESTAMP NOT NULL,
    expires_at TIMESTAMP NOT NULL,
    status ENUM('ACTIVE', 'EXPIRED', 'CLOSED') DEFAULT 'ACTIVE',
    qr_token VARCHAR(500) NOT NULL,
    valid_duration_minutes INT DEFAULT 5,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    FOREIGN KEY (lab_id) REFERENCES labs(id),
    FOREIGN KEY (created_by) REFERENCES users(id)
);

AttendanceRecord (출석 기록):
CREATE TABLE attendance_records (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    session_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    status ENUM('ABSENT', 'PRESENT', 'LATE') DEFAULT 'ABSENT',
    checked_at TIMESTAMP NULL,
    corrected_at TIMESTAMP NULL,
    corrected_by BIGINT NULL,
    correction_reason VARCHAR(500),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    FOREIGN KEY (session_id) REFERENCES attendance_sessions(id),
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (corrected_by) REFERENCES users(id),
    UNIQUE KEY unique_session_user (session_id, user_id)
);

📌 4. 랩실 랭킹 기능 (상세 확정)

🔖 4.1 점수 신청 시스템
	•	점수 신청 방식: 자유 신청 (언제든지 가능)
	•	신청 필수 정보: 카테고리, 성과내용, 취득일자, 증빙서류
	•	신청 선택 정보: 신청 사유, 관련 링크, 공개/비공개 설정
	•	파일 업로드 제한: PDF, 이미지 파일 (JPG, PNG, JPEG), 개당 10MB 이하
	•	파일 검증: MIME 타입 + 파일 내용 검증 (악성 파일 방지)
	•	업로드 실패 시: 신청 전체 삭제 처리
	•	보안 검증: 확장자, MIME 타입, 매직 넘버 검증 단계적 적용

🔖 4.2 점수 카테고리 및 배점 기준
	•	학업 성과
		- 전공 A+ 취득: 5점/과목
		- 학과 성적 장학금: 15점
		- 학점 4.0 이상 유지: 10점/학기
	•	대회 수상
		- 교내 대회: 대상 30점, 금상 20점, 은상 10점
		- 교외 대회: 대상 50점, 금상 30점
	•	자격증
		- 국가 기술자격증: 20점
		- 국제 인증 자격증: 25점
		- 민간 자격증: 10점
	•	교육/연수
		- 교육 프로그램 수료: 10점
		- 외부 세미나 참석: 5점
	•	연구 활동
		- 논문 게재 (SCI): 100점
		- 논문 게재 (일반): 50점
		- 특허 출원: 30점
	•	카테고리 관리: 개발자가 개발시 수정 (수정하기 쉽도록 코드 설계)
	•	점수 수정 적용: 기존 점수에 소급 적용

🔖 4.3 승인 프로세스
	•	승인 권한: 해당 랩의 랩장 + admin, 교수 (모든 랩실 기여 가능)
	•	승인 기한: 6개월 (기한 초과 시 자동 거부)
	•	자동 거부 후: 재신청 가능
	•	승인자 기록: 승인 후 승인자 정보 저장
	•	동시 승인 방지: 먼저 승인한 사람 기준으로 처리

🔖 4.4 중복 방지 시스템
	•	중복 검사 기준: 카테고리, 취득일자 조합
	•	구현 방식: 애플리케이션 로직 + 데이터베이스 유니크 제약조건 조합
	•	날짜만 중복: 노란색 경고 + 상단 배치 + 사용자 가이드 제공
	•	날짜 + 카테고리 모두 중복: 빨간색 테두리 경고 + 상단 배치 + 중복 해결 안내
	•	중복 확인: 승인 전 신청자의 모든 기록 조회 후 최종 승인
	•	동시성 제어: 데이터베이스 제약조건으로 Race Condition 방지

🔖 4.5 점수 정정 시스템
	•	정정 권한: 승인 권한이 있는 모든 사람 (랩장, admin, 교수)
	•	정정 횟수: 한번만 가능
	•	상태 변경 규칙:
		- 승인 → 거절: 언제든지 가능
		- 거절 → 승인: 정정 내역이 한번도 없을 때만 가능
	•	기록 보관: 정정 이유만 보관, 최초 승인자도 기록

🔖 4.6 랭킹 시스템
	•	랩실 점수 산정: 부원들 총합점수
	•	다중 소속 처리: 현재 미지원 (단일 랩실 소속만 지원)
	•	동점 처리: 동점자들 모두 같은 등수 (1, 2, 2, 4등)
	•	랭킹 업데이트: 실시간 처리 → 추후 배치 처리 전환 (설정 기반)
	•	성능 최적화: 캐싱 전략 적용 (랩별 점수 캐시 + 전체 랭킹 캐시)
