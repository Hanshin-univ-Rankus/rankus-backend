🔖 3.3 캘린더 기능 [대폭 개편 - 페이지 분리]

🎯 3.3.1 캘린더 시스템 개요
	•	핵심 컨셉: 일반일정과 면접일정 완전 분리
	•	페이지 구성: 별도 페이지로 완전 분리된 캘린더 시스템
	•	기술 철학: 각 캘린더의 고유 목적에 집중한 전용 인터페이스

🔧 3.3.2 일반일정 캘린더 페이지

페이지 구성:
	•	독립 페이지: /labs/{labId}/calendar/schedules
	•	페이지 제목: "일반일정 캘린더"
	•	네비게이션: 상단 탭으로 면접일정 캘린더 이동 가능

기능:
	•	일반일정 생성: 시간이 없는 종일 이벤트 생성
		- 일정 제목, 내용, 날짜, 장소 입력
		- 관련 공지사항 연결 기능 (다:다 관계)
	•	일정 수정: 생성된 일정 정보 변경
	•	일정 삭제: 불필요한 일정 제거
	•	일정 상세 보기: 개별 일정의 자세한 정보 표시

화면 구성:
	•	월별 캘린더 뷰: 한 달 전체 일정 표시
	•	색상 구분: 초록색 계열로 통일
	•	일정 표시: 각 날짜에 최대 3개 일정 표시
	•	더보기 기능: 3개 초과 시 "더보기" 버튼 표시
	•	액션 버튼: "새 일정 추가" 버튼 (권한 있는 사용자만)

일정 상세 화면:
	•	기본 정보: 제목, 내용, 날짜, 장소
	•	연결된 공지사항: 관련 공지사항 목록 표시
		- 공지사항 제목, 요약, 작성일 표시
		- 공지사항 바로가기 링크 제공
	•	편집 권한: 권한 있는 사용자만 수정/삭제 가능

🔧 3.3.3 면접일정 캘린더 페이지

페이지 구성:
	•	독립 페이지: /labs/{labId}/calendar/interviews
	•	페이지 제목: "면접일정 캘린더"
	•	네비게이션: 상단 탭으로 일반일정 캘린더 이동 가능

기능 (자동 관리):
	•	자동 생성: 면접 생성 시 캘린더에 자동 추가
		- 면접 시작일과 종료일에 각각 캘린더 이벤트 생성
		- 기본 시간: 9:00-18:00 (면접 가능 시간대)
		- 생성자: 랩장 자동 설정
	•	자동 업데이트: 지원자 신청 시 이름 자동 표시
		- 지원자 실명으로 표시 (예: "김학생, 이학생")
	•	상태 동기화: 면접 상태 변경 시 캘린더 반영
		- 면접 취소 시 캘린더에서도 취소 표시
	•	수정 제한: 자동 생성된 면접 일정은 수정 불가
	•	완료 처리: 면접 완료 후 관리자가 수동으로 완료 처리

화면 구성:
	•	월별 캘린더 뷰: 면접 일정만 표시
	•	색상 구분: 주황색 계열로 통일
	•	상태 표시: 예정/진행/완료/취소 상태별 시각적 구분
	•	필터 기능: 상태별 필터 (예정/진행/완료/취소)
	•	액션 버튼: "면접 완료 처리" 버튼 (권한 있는 사용자만)

면접 상세 화면:
	•	기본 정보: 면접 제목, 날짜, 시간 (9:00-18:00)
	•	면접 정보: 면접실, 면접 기간 (시작일~종료일)
	•	지원자 정보: 지원자 실명 목록
	•	슬롯 정보: 실제 면접 가능 시간대 목록
	•	상태 정보: 현재 면접 상태
	•	주의사항: 실제 신청은 관리자가 생성한 면접 슬롯 시간에만 가능

🔧 3.3.4 면접 시스템 연동 상세

자동 연동 기능:
	•	면접 생성 시: Interview 생성 시 캘린더 이벤트 자동 생성
		- 면접 시작일 캘린더 이벤트: "면접 시작 - {랩실명}"
		- 면접 종료일 캘린더 이벤트: "면접 종료 - {랩실명}" (시작일과 다른 경우)
	•	지원자 신청 시: LabApplication 생성 시 지원자 이름 자동 표시
		- 지원자 목록 실시간 업데이트
		- 지원자 없을 시: "지원자 모집중" 표시
	•	면접 취소 시: Interview 상태 변경 시 캘린더 자동 반영
		- 면접 상태 CLOSED → 캘린더 상태 CANCELLED

면접 캘린더 특징:
	•	시간 표시: 9:00-18:00 (면접 가능 시간대 표시)
	•	실제 운영: 관리자가 생성한 InterviewSlot 시간에만 실제 신청 가능
	•	지원자 표시: 실명으로 표시 (개인정보 보호 논의 완료)
	•	완료 처리: 면접 완료 후 관리자가 수동으로 완료 처리
	•	데이터 일관성: 면접 시스템에서만 수정 가능 (캘린더에서 수정 불가)

🔧 3.3.5 캘린더 네비게이션 및 공통 기능

페이지 간 전환:
	•	탭 방식: 페이지 상단에 "일반일정" / "면접일정" 탭 배치
	•	즉시 전환: 탭 클릭 시 해당 캘린더 페이지로 즉시 이동
	•	상태 유지: 월/년도 선택 상태는 페이지 전환 시에도 유지

공통 기능:
	•	월 이동: 이전/다음 달 이동 버튼
	•	오늘로 이동: 현재 날짜로 이동 버튼
	•	새로고침: 최신 정보 업데이트 버튼
	•	반응형 디자인: 모바일 환경에서도 최적화된 사용자 경험

🔧 3.3.6 권한 체계

권한별 기능:

🔧 3.3.7 데이터 모델 설계

캘린더 이벤트 공통:
CREATE TABLE calendar_events (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(255) NOT NULL,
    description TEXT,
    date DATE NOT NULL,
    type ENUM('SCHEDULE', 'INTERVIEW') NOT NULL,
    status ENUM('SCHEDULED', 'COMPLETED', 'CANCELLED') NOT NULL,
    lab_id BIGINT NOT NULL,
    created_by BIGINT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    FOREIGN KEY (lab_id) REFERENCES labs(id),
    FOREIGN KEY (created_by) REFERENCES users(id)
);

일반일정 상세:
CREATE TABLE schedule_events (
    id BIGINT PRIMARY KEY,
    location VARCHAR(255),
    is_all_day BOOLEAN DEFAULT TRUE,
    FOREIGN KEY (id) REFERENCES calendar_events(id) ON DELETE CASCADE
);

면접일정 상세:
CREATE TABLE interview_events (
    id BIGINT PRIMARY KEY,
    start_time TIME NOT NULL,
    end_time TIME NOT NULL,
    interview_room VARCHAR(255) NOT NULL,
    applicant_name VARCHAR(500),
    interview_id BIGINT,
    interview_slot_id BIGINT,
    is_auto_generated BOOLEAN DEFAULT TRUE,
    FOREIGN KEY (id) REFERENCES calendar_events(id) ON DELETE CASCADE
);

공지사항 연결:
CREATE TABLE schedule_event_notices (
    schedule_event_id BIGINT,
    notice_id BIGINT,
    PRIMARY KEY (schedule_event_id, notice_id),
    FOREIGN KEY (schedule_event_id) REFERENCES schedule_events(id) ON DELETE CASCADE,
    FOREIGN KEY (notice_id) REFERENCES lab_notices(id) ON DELETE CASCADE
);

🔧 3.3.8 API 설계

일반일정 캘린더 API:
	•	GET /api/labs/{labId}/calendar/schedules - 일반일정 월별 조회
	•	POST /api/labs/{labId}/calendar/schedules - 일반일정 생성
	•	PUT /api/labs/{labId}/calendar/schedules/{eventId} - 일반일정 수정
	•	DELETE /api/labs/{labId}/calendar/schedules/{eventId} - 일반일정 삭제
	•	GET /api/labs/{labId}/calendar/schedules/{eventId} - 일반일정 상세 조회
	•	POST /api/labs/{labId}/calendar/schedules/{eventId}/notices/{noticeId} - 공지사항 연결
	•	DELETE /api/labs/{labId}/calendar/schedules/{eventId}/notices/{noticeId} - 공지사항 연결 해제

면접일정 캘린더 API:
	•	GET /api/labs/{labId}/calendar/interviews - 면접일정 월별 조회
	•	GET /api/labs/{labId}/calendar/interviews/{eventId} - 면접일정 상세 조회
	•	POST /api/labs/{labId}/calendar/interviews/{eventId}/complete - 면접 완료 처리
	•	GET /api/labs/{labId}/calendar/interviews?status=SCHEDULED - 상태별 면접일정 조회

🔧 3.3.9 사용자 경험 요구사항

일반일정 캘린더 사용 흐름:
	1.	메인 메뉴에서 "일반일정 캘린더" 선택
	2.	월별 뷰에서 일반 일정들 확인 (초록색 표시)
	3.	원하는 날짜 클릭하여 새 일정 추가
	4.	일정 제목, 내용, 장소 입력
	5.	관련 공지사항 선택 (선택사항)
	6.	저장 버튼 클릭하여 일정 생성

면접일정 캘린더 사용 흐름:
	1.	페이지 상단 탭에서 "면접일정 캘린더" 선택
	2.	월별 뷰에서 면접 일정들 확인 (주황색 표시)
	3.	면접 일정 클릭하여 상세 정보 확인
	4.	지원자 목록, 면접 시간, 면접실 정보 확인
	5.	면접 완료 후 "완료 처리" 버튼 클릭

🔧 3.3.10 캘린더 개발 우선순위

Phase 2: 완성도 (1주)
	•	3주차: 공지사항 연결 기능 구현
	•	3주차: 면접 완료 수동 처리 기능
	•	3주차: 페이지 분리 및 탭 네비게이션 구현
	•	3주차: 테스트 작성 및 통합 테스트
