# Request DTO 컨벤션

> 📋 **네이밍 규칙**: @core/conventions.md#dto  
> 🏗️ **기본 패턴**: @core/patterns.md (향후 추가 예정)

## 🎯 핵심 규칙

### 네이밍
- **클래스**: `{Domain}{Action}RequestDto`
- **필드**: camelCase, boolean은 `isActive` 선택적

### 기본 구조 (Lombok 권장)
```java
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class {Domain}{Action}RequestDto {
    @NotBlank(message = "{필드}는 필수입니다")
    @Size(max = 30, message = "{필드}는 30자 이하여야 합니다")
    private String name;
    
    @Email @Size(max = 100)
    private String email;
    
    @NotNull
    private Role role;
}
```

## ✅ 검증 어노테이션 매트릭스

### 주요 검증 패턴
| 타입 | 어노테이션 | 사용 케이스 | 메시지 패턴 |
|------|------------|-------------|-------------|
| 필수 | `@NotBlank` | 문자열 필수 | "{필드}는 필수입니다" |
| 길이 | `@Size(max=30)` | 문자열 길이제한 | "{필드}는 30자 이하여야 합니다" |
| 범위 | `@Size(min=8, max=255)` | 비밀번호 등 | "{필드}는 8-255자여야 합니다" |
| 이메일 | `@Email` | 이메일 형식 | "올바른 이메일 형식이 아닙니다" |
| URL | `@Pattern(regexp="^(https?\\|ftp)://.*$")` | 이미지 URL | "올바른 URL 형식이 아닙니다" |
| 숫자 | `@Min(0)` / `@Max(100)` | 정수 범위 | "0 이상이어야 합니다" |
| 시간 | `@Future` | 미래 시점 | "미래 시점이어야 합니다" |

### 고급 검증 패턴
| 타입 | 패턴 | 사용 케이스 |
|------|------|-------------|
| 중첩 객체 | `@Valid` | DTO 내부 객체 검증 |
| 컬렉션 | `@NotEmpty @Size(min=1, max=10)` | 리스트 크기 제한 |
| 커스텀 | `@UniqueEmail` | 비즈니스 규칙 검증 |

## 🎯 메시지 표준화

### 메시지 패턴 가이드
| 검증 타입 | 표준 메시지 패턴 |
|-----------|------------------|
| 필수 | "{필드명}은 필수입니다" |
| 길이 | "{필드명}은 {숫자}자 이하여야 합니다" |
| 범위 | "{필드명}은 {최소}자 이상 {최대}자 이하여야 합니다" |
| 형식 | "올바른 {형식} 형식이 아닙니다" |
| 시간 | "{필드명}은 미래 시점이어야 합니다" |

## 🎯 주요 규칙 요약

1. **명확한 네이밍**: 도메인과 액션 포함
2. **철저한 검증**: 모든 입력 필드 검증
3. **일관된 메시지**: 표준 메시지 패턴 사용
4. **단순한 역할**: 데이터 전달에만 집중
5. **테스트 가능**: 검증 로직 충분한 테스트
